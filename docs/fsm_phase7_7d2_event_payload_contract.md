# Potok 7D-2 — Ephemeral typed event-payload operand for Condition Tok

Date 2026-11-01. Branch `feature/fsm-runtime-flow-flusso`. Begin on 7D-1 green baseline, [CI 41381250681](https://github.com/mercurysama/Flujo/actions/runs/41381250681).

## Contractual clock semantics
- The authored Condition Tok can reference one event's field with `FlowEventPayloadValueSource`: `event_name: StringName`, `field_name: String`, `value_type: Variant.Type` (only BOOL, INT, FLOAT, STRING) and stable `source_id`. The source does not store actual event data; only an authored type declaration and names. No auto inference from a past packet, no implicit numeric or String coercion.
- Runtime context `FlowValueResolutionContext` owns **ephemeral** per-machine-per-matching-tick event packets. At the start of the current machine's event delivery, discard earlier packets. As each admitted event packet is delivered to that machine, store a **deep copy of the last packet for each event_name** (FIFO overwrites only its own name). Sources resolve only that named event's named top-level field, and fail with explicit `event_payload_missing` or `event_payload_type_mismatch` diagnostics on absent data or exact Variant.Type mismatch. Never treat absence as false, 0, or `null`; a literal source is required for defaults.
- `_pick_condition()` runs **after** matching-clock event delivery only when the existing direct/EVENT candidate is absent; condition resolution sees that machine's same-tick packet map. Clear the map **before** Exit/Enter/commit callbacks, and on stop. No retained snapshot, no cross-controller or cross-machine access, no event rewriting, no new serialized packet or machine state. A normal EVENT transition still takes precedence over CONDITION fallback; payload conditions do not override priority rules across trigger types.
- A callback-generated event is deferred to its next matching tick exactly as before (6B and 6G); it cannot become visible in the current tick. Other-clock packets are invisible; one machine's events never leak to its sibling. Conditions with event payload sources on ticks without a matching event fail safely and cannot activate a transition. Only JSON-safe inbound `emit_event` packets reach the context.
- `FlowConditionValueSource` admits the new source kind and performs explicit structural/type checks. Visual `FlowConditionEditor` offers **Event field** kind only when the Potok context flag is enabled (or when rendering an already-authored event field). Name/key and exact type must be explicitly selected; preview displays the declared event/key, does not pretend to have a runtime value. An incomplete draft cannot be Confirmed. Existing Condition Tok variable/literal/node/operation modes stay unchanged.
- No new graph schema version or runtime API signature. Add headless model/runtime and editor focals, proof of RED before change, then full regression CI. No manual Android or human UI approval inferred.

## Deliberate limitations
Only top-level Dictionary key with type bool/int/float/String is supported. There is no array path/indexing, typed nested object, auto conversion, machine-to-machine event forwarding, arithmetic expression output, payload access from StateEnter/Exit, or event payload broadcast. Condition evaluation is a **fallback on an unmatched/nonwinning EVENT**, not a filter on a preselected EVENT edge. These extensions need independent contracts, not silent feature claims.
